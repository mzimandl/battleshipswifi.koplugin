# KOReader Battleships (Wi-Fi)
- Repo root is the plugin folder (battleshipswifi.koplugin). Plugin id, folder and module are `battleshipswifi` since 0.2.0 (before: `battleships`, renamed like backgammonwifi.koplugin to stay clear of other plugins in ZenPM); init() copies name/last_address from the old battleships.lua settings once (setting `migrated`; until 1.1.3 it ran on every start while no name was set and brought the old address back). Pure-Lua modules in battleshipswifi/ must not require KOReader modules (testable off-device); net.lua gets LuaSocket passed in.
- Only main.lua touches KOReader APIs. Verify API names against koreader/koreader source before using them.
- LuaJIT 2.1 / Lua 5.1: no utf8 library, no goto.
- Pass Blitbuffer only whole-pixel coordinates (round them): with 32-bit LuaJIT (Kindle) `stride` is a plain number and setPixel's `data + stride * y + x` turns a fractional y into a shift by part of a row, so shapes scatter there while they look right on 64-bit (desktop, Android). smoke.lua's fake buffer fails on fractional painting arguments.
- Tests: `luajit tests/run.lua` (board, protocol, two Match instances wired together, net with fake sockets, translations) and `luajit tests/smoke.lua` (main.lua against stubbed KOReader modules and a fake `socket`) must pass before finishing any change (`lua5.1` works too). smoke.lua finds menu items by their `battleshipswifi_item` field.
- Translations: main.lua's `_` (battleshipswifi/l10n.lua) looks up battleshipswifi/l10n/<lang>.lua first. Every new `_("…")` needs an entry in battleshipswifi/l10n/cs.lua (run.lua checks both ways); _meta.lua keeps its Czech inline. Czech texts avoid past-tense verbs with a player name (gender unknown): "%1 odchází", "Vyhrává %1".
- Distributed through ZenPM from mzimandl/koplugins (manifest.json, installs the master branch zip). ZenPM offers an update only when `version` in _meta.lua grows: bump it for every change that should reach devices. A push to master that changes _meta.lua asks koplugins to sync at once (.github/workflows/notify-koplugins.yml, secret KOPLUGINS_TOKEN).
- Own modules must be required at load time from main.lua (PluginLoader only adds the plugin folder to package.path while main.lua loads).

## Modules
- board.lua: SHAPES (squares of each ship shape), FLEETS (`classic` = straight line5…line2, `shapes` = carrier, cruiser, battleship, destroyer, 2 submarines; the host picks, sent in GAME and WELCOME). Board (own ships + opponent's shots: shoot() → miss/hit/sunk/won), Target (what we know of the opponent's board; "near" = water around a sunk ship, auto-marked since ships may not touch). 0-based x/y, ship = { shape, x, y (top left of its bounding box), rot (index into rotations(shape): the distinct quarter turns, then the new mirrored orientations, so version-2 indices stayed), hits }, wire form "x,y,shape,rot". A ship moves and turns by its anchor (first square of its top row). Placing: placed(i, x, y, rot) is the one check behind move()/rotate()/can_rotate()/blocked() (squares shaded for the selected ship), so the shading always matches what a tap does. turned()/rotate() stay on the ship's side (mirrored or not); mirrored()/mirror() flip it around its anchor (Board.mirrored(shape, rot)). position() is placed() without the fit check (the drag preview).
- Rules (board.lua M.rules(): size 10/12, salvo, touch; encode_rules() "12st"): Board.new(fleet, rules) / Board.target(rules) carry size and touch (inside(x, y, size), square keys y * KEY + x); match.lua takes them from opts (host) or WELCOME, sends them in WELCOME and GAME, counts salvo shots in after_shot() (`shots_left`, afloat(side): both sides compute the same, no extra lines). The menu's rulesItems() (Board submenu of radio items from Board.SIZES, check boxes for salvo and touch; settings rules_size/rules_salvo/rules_touch) feed gameRules().
- protocol.lua: line format (documented at its top), Buffer for partial TCP reads, address parsing, discovery messages, ports. VERSION 4 since 1.1.0 (rules in WELCOME/GAME), 3 since 1.0.0 (mirrored ship orientations), 2 since 0.3.0 (fleets; version 1 had "x,y,len,dir" ships).
- match.lua: state machine of one match (phases placing → battle → over, rematch back to placing). receive(line) → event | nil | nil, error; local actions set_ready()/fire()/request_rematch(). The host sends START (random first player). Unknown commands are ignored, so new commands can be added without breaking older versions; changing the meaning of existing ones needs Protocol.VERSION + 1 (both sides refuse other versions).
- ai.lua: the e-reader as an opponent. choose(level, target, fleet, rand): easy (random, follows hits half of the time), normal (checkerboard hunt + finish along the line of hits), hard (density(): placements of the ships afloat consistent with the marks and no-touching, through the open hits when there are any). player(): its own Match (role "guest") fed by deliver(line); poll(now) gets ready, agrees to rematches, fires after `delay` and returns its lines for the human's match. tests/run.lua checks that harder levels need fewer shots.
- Score and numbers (match.lua): `score` (games won against this opponent, kept by reset()/rematch, cleared for a new opponent) and `stats` (this game's shots per side, record()), counted in the SHOT/RESULT handlers, so a resumed game counts every shot once. main.lua shows the score in the title and the numbers in the status line after the game (instead of the last shot's message); RESULT_TEXT/INCOMING_TEXT name the sunk ship (SHIP_NAMES by shape).
- net.lua: non-blocking Conn (out buffer for partial sends), Host (TCP listener + UDP discovery answers), Search (DISCOVER broadcasts to 255.255.255.255 and the /24 broadcast, games list with expiry).

## main.lua
- Menu (gameMenu()): Continue (if saved), Play against the e-reader, Host a game (both: startItems() = Start game + Ships submenu (radio, setting `fleet`, fleet()), then the rules, the e-reader's Difficulty), Find a game (its list ends with Join by address…, setting `last_address`), Settings (name, animations), Rules.
- State is module-level (`game`, `finder`), not on `self`: KOReader makes a new plugin instance for every reader/file manager.
- Sockets are polled from UIManager ZMQs (poller(): waitEvent() runs every ~50 ms and must return nil). preventStandby() while a game runs; onSuspend/onExit end the game and the search.
- GameScreen rebuilds its whole widget tree on every update() (build()); status text comes from the match state plus `game.message` (last event). The status line keeps room for 3 lines while placing, 2 in the battle (status_min_height(width, lines)), so the boards don't move when its text changes; battle texts are short ("Your turn.", the whole hint only before our first shot). No board labels; the opponent and the score are in the title (no subtitle line); the target board gets TARGET_SHARE of the room. update(hint) after a shot ({ board, cells }) refreshes only the status line, the old last-shot outline and the shot's squares + neighbours, as long as `self.layout` (what decides where things are) stayed the same; else, and without a hint, the whole screen ("ui"). Our shot shows its shell at once on tap (anim kind "shell", until the RESULT; the miss/hit then goes on from frame 2). BoardWidget paints the grid itself (Blitbuffer paintRect/paintRoundedRect/paintCircle/paintBorder; explosions are star polygons filled row by row, fill_polygon) and maps taps to cells. Grid lines are painted first, then the squares: a ship's squares join across the lines (paintHull) into one silhouette.
- Dragging ships while placing: BoardWidget's on_drag (pan / pan_release (anywhere on the screen, off the board = cancel) / swipe) → GameScreen:onDrag(): `self.drag` = { i, dx, dy (square held, from the anchor), ship (Board:position()), fits }, drawn by paintDrag(); on each new square the board alone is repainted (paintRegion()) with a fast refresh, after waitForVSync(). The Mirror button (shaped fleet only) mirrors the selected ship.
- Keys (GameScreen key_events): with a D-pad, KeyMove (arrows, wraps), KeyAct (Press = a tap on the cursor's square: onOwnTap/onTargetTap), KeyStep (page keys: row by row, in the battle to squares not fired at); without, page back steps and page forward acts. The cursor (`self.cursor`, shown once a key is used, on cursorBoard(): own while placing, target in the battle) is drawn by BoardWidget (`cursor`) and refreshed like a drag preview (paintRegion + fast). Menu (onKeyMenu) puts buttonRow() in a ButtonDialog (FocusManager: works with keys).
- FleetWidget: the opponent's fleet in small below their board (ships afloat dark, sunk light and crossed out; sunk_ships() matches target.ships to the fleet by shape, revealed ones don't count). Its square size comes from the target board's width; update(hint) refreshes it when the sunk count changed.
- Animations (setting `animations`, default on, copied to `game.animations`): onGameEvent result/incoming → GameScreen:animateShot() → self.anim, which build() hands to the matching BoardWidget (`anim`). frame_count(): miss 6, hit 5, sunk min(squares, SINK_STEPS) + 3. paintCell draws the animated squares as before the shot, then paintTo calls paintAnim() over the whole board, as effects spill onto the neighbours (region() = the squares + 1 around, labels included). Frame 1 shows with the normal update; animationStep() (UIManager:scheduleIn, FRAME_TIME) bumps anim.frame, waits for the previous refresh (UIManager:waitForVSync()), copies just the region to Screen.bb (BoardWidget:paintRegion(), without repainting GameScreen) and setDirty(nil, "fast", region); the last step "ui" to clean the ghosting. When another window is on top it stops and refreshes the game normally. Frames are pure black/white (fast refreshes are DU/A2).
- Never paint the screen in place while the e-ink controller may still be reading it (a refresh in progress): the picture tears, e.g. half the screen white. So GameScreen and an animated BoardWidget paint into off-screen canvases (canvas_for(), reused per size, freed in endGame()) and blit the finished pixels; animation effects are clipped to the board that way, too. So everything a widget paints must lie within its dimen (BoardWidget's includes the outer grid line, 2 × line past the last square). A new animation, rematch or closing the screen unschedules the old one; a new animation replacing an unfinished one (the next shot came first, e.g. against the e-reader) gives the old squares their clean-up refresh (stopAnimation(true)), except our shell that goes on as the result. The clean-up refresh is CLEANUP_REFRESH ("partial": the full waveform clears what the fast frames leave).
- Against the e-reader (playAgainstReader(fleet), level in setting `ai_level`): the human's match is the host, `game.ai` the AI.player; poll_game() moves lines between them (handle_line(), shared with the network path), no sockets, no preventStandby() (`game.standby` only for network games), and onSuspend keeps the game.
- Resuming (Match: SESSION/RESUME/RESUMED, `log` + `received`; see protocol.lua): connection_lost(reason, resumable) with a network loss and m:can_resume() sets `game.waiting` instead of `game.lost`. Host: keeps listening, answers searches with RESUMEGAME, takes a new connection whose first line is RESUME even while it still has the old one (`game.candidate`, poll_candidate()); while waiting, a protocol error only drops that connection. Guest: `game.reconnect`, poll_reconnect(): Net.connect_async() every RECONNECT_INTERVAL to the last address or to the one found by Search (`resumes`), then m:resume(). onSuspend keeps a resumable game (closes the sockets, no BYE, `game.paused`), onResume lets the polling start again (host rebinds, `rebind_at`). The "resumed" event clears `waiting`.
- Surviving a restart: save_game() (called from GameScreen:update(), so after every change) writes Match:snapshot() (and the e-reader's) to settings/battleshipswifi_game.lua when the game can go on (against the e-reader, or m:can_resume()), else drops it; endGame() drops it, endGame(true) (onExit) keeps it and sends no BYE. The menu's first entry is then Continue (continueSaved()): startGame{ restore } with Match.restore() / AI.player{ restore }; a network game starts out `waiting` (host rebinds, guest reconnects), against the e-reader both matches send_again() what the other missed.
- Host: the guest leaving before the battle (or timing out) frees the seat (Match:drop_peer()); a second guest while one is connected gets ERROR busy. After the battle starts any loss ends the game (`game.lost`).
- Kindle: iptables rules opened per role (host_rules / guest_rules / search_rules) and removed with the same list.
